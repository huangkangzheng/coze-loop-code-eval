# 功能规格说明: Code评估器
## 澄清记录

### Session 2025-11-06

- Q: 模板选择流程是否仅适用于Code评估器? → A: 不是,模板选择流程应该应用于所有类型的评估器(LLM和Code),无论创建任何类型的评估器都需要先选择模板再进行具体配置
- Q: 边缘情况需要明确处理方案吗? → A: 是的,所有边缘情况都需要提供明确的处理方案,包括具体的错误提示文案、超时时间、确认对话框等实现细节,确保开发时不会产生歧义
- Q: Code评估器配置界面的结构是怎样的? → A: Code评估器配置界面的进入形式和整体结构与LLM评估器配置界面完全一致,都包含"基础信息"和"配置信息"两部分。基础信息的表单内容与LLM评估器保持一致,差异仅在于配置信息部分(Code评估器显示执行函数体和测试数据,LLM评估器显示提示词等配置)
- Q: FR-204中的"左侧"和FR-210中的"右侧"具体指什么位置? → A: 在"配置信息"区域内采用左右两栏布局。左侧栏显示"执行函数体"配置区域(包含语言选择和代码编辑器),右侧栏显示"测试数据"配置区域(包含JSON编辑器)。这种左右分栏布局使得用户可以同时查看和编辑执行函数体和测试数据,提升配置效率
- Q: 测试数据JSON格式错误时是否应该阻断试运行? → A: 不应该阻断。当测试数据JSON格式错误时,编辑器内会显示语法报错提示(如高亮错误位置),但用户仍可以点击"试运行"按钮。试运行会在执行时因为JSON格式问题而运行失败,并在试运行结果中显示具体的错误信息
- Q: 切换模板时是否需要二次确认弹窗? → A: 不需要。当用户编辑了配置内容后点击"选择模板"按钮并选择新模板时,直接用新模板内容覆盖当前配置内容(评估器名称除外),无需弹出确认对话框。这样可以简化交互流程,提升用户操作效率

## 用户场景与测试 _(必填)_

### 用户场景 1 - 使用模板快速创建评估器 (优先级: P1)

用户想要创建一个新的评估器(Code类型或LLM类型)来评估AI输出质量。为了降低启动成本,用户希望能够在创建流程的第一步就看到并选择预置的评估器模板,然后基于模板快速配置自己的评估器。**此流程适用于所有类型的评估器**,无论是创建Code评估器还是LLM评估器,都需要先选择模板,再进行具体配置。

**为什么是此优先级**: 这是整个功能的核心价值主张 - 通过模板前置降低用户的学习和使用成本,让用户能够快速上手评估器。这是MVP的基础功能,同时也是对现有LLM评估器创建流程的改进。

**独立测试**: 可以通过以下操作独立测试:用户悬停在"新建评估器"按钮上,选择"Code评估器"或"LLM评估器",从对应类型的模板列表中选择一个预置模板,确认后查看配置表单是否正确预填充了模板内容,并能够成功创建评估器。

**验收场景**:

1. **Given** 用户在评估器列表页面, **When** 用户将鼠标悬停在"新建评估器"按钮上, **Then** 系统显示包含"LLM评估器"和"Code评估器"两个选项的下拉菜单
2. **Given** 用户点击了"Code评估器"选项, **When** 系统展示"选择模板"弹窗, **Then** 弹窗左侧显示5个预置Code评估器模板列表(文本包含判断、文本等值判断、JSON格式校验、文本正则匹配、文本起始子串判断),右侧以代码编辑器形式展示选中模板的执行函数代码,右上角提供Python/Javascript语言切换下拉菜单
3. **Given** 用户点击了"LLM评估器"选项, **When** 系统展示"选择模板"弹窗, **Then** 弹窗左侧显示预置LLM评估器模板列表,右侧展示选中模板的配置详情
4. **Given** 用户在Code评估器模板列表中选择了"文本等值判断"模板, **When** 用户点击"确定"按钮, **Then** 系统进入配置表单页面,评估器名称预填为"文本等值判断",执行函数体代码区域预填充对应模板的代码内容
5. **Given** 用户在LLM评估器模板列表中选择了某个模板, **When** 用户点击"确定"按钮, **Then** 系统进入配置表单页面,评估器名称和配置内容按照LLM模板进行预填充
6. **Given** 用户在配置表单页面填写了基础信息, **When** 用户点击"创建"按钮并通过检查, **Then** 系统成功创建评估器,并自动跳转到评估器详情页
7. **Given** 用户在"选择模板"弹窗中, **When** 用户点击右上角关闭按钮, **Then** 弹窗关闭且终止新建流程
8. **Given** 用户在"选择模板"弹窗中, **When** 用户点击弹窗外的蒙层区域, **Then** 弹窗不会关闭

**功能需求**:

- **FR-101**: 系统必须在用户鼠标悬停"新建评估器"按钮时显示包含"LLM评估器"和"Code评估器"的下拉菜单
- **FR-102**: 系统必须在用户点击"Code评估器"或"LLM评估器"后展示"选择模板"弹窗作为创建流程的第一步
- **FR-103**: 当用户选择"Code评估器"时,"选择模板"弹窗必须提供5个预置Code评估器模板:文本包含判断、文本等值判断、JSON格式校验、文本正则匹配、文本起始子串判断
- **FR-104**: Code评估器的每个模板必须同时提供Python和Javascript两种语言版本的执行函数代码
- **FR-105**: 当用户选择"LLM评估器"时,"选择模板"弹窗必须提供预置LLM评估器模板列表(模板内容与现有LLM评估器模板保持一致)
- **FR-106**: 对于Code评估器模板,弹窗左侧必须展示模板列表,右侧必须以代码编辑器形式展示选中模板的执行函数代码,右上角必须提供Python/Javascript语言切换下拉菜单
- **FR-107**: 对于LLM评估器模板,弹窗左侧必须展示模板列表,右侧必须展示选中模板的配置详情
- **FR-108**: 默认必须选中第一个模板
- **FR-109**: 弹窗下方必须提供"使用自定义创建"和"确定"两个按钮
- **FR-110**: 点击"确定"按钮后必须进入配置表单页面,评估器名称预填为选中模板名称,配置内容预填为选中模板的内容
- **FR-111**: 点击"使用自定义创建"按钮后必须进入配置表单页面,所有配置项为初始化内容(不使用模板预填充)
- **FR-112**: 弹窗右上角必须提供关闭按钮,点击后关闭弹窗并终止新建流程
- **FR-113**: 点击弹窗外蒙层区域时弹窗不能关闭

**边缘情况与处理方案**:

- **快速切换语言(Code评估器)**: 当用户快速连续切换语言时,系统必须使用防抖机制(debounce),延迟300ms后再更新代码编辑器内容,避免中间状态显示和性能问题
- **关闭模板选择弹窗**: 当用户选择了模板但未点击确定就关闭弹窗时,系统必须清除选择状态,下次打开弹窗时重新默认选中第一个模板
- **LLM模板迁移**: 现有LLM评估器的模板数据必须保持不变,在新流程中直接复用现有模板配置,确保向后兼容。系统必须支持旧版本直接创建(不经过模板选择)和新版本模板选择两种创建方式的平滑过渡

### 用户场景 2 - 配置和调试Code评估器执行函数 (优先级: P1)

用户已经选择了一个Code评估器模板(或选择自定义创建),系统进入Code评估器配置界面。**此配置界面的进入形式和整体结构与LLM评估器配置界面完全一致**,包含"基础信息"和"配置信息"两个部分。基础信息的表单内容与LLM评估器保持一致(名称、描述等),差异在于配置信息部分:Code评估器需要配置执行函数体和测试数据,而LLM评估器配置提示词等内容。用户需要编辑执行函数体、准备测试数据,并通过试运行功能验证代码逻辑是否正确。

**为什么是此优先级**: 这是创建Code评估器的核心配置环节,用户必须能够编辑和调试代码才能完成评估器的创建。试运行功能是确保代码质量的关键。保持与LLM评估器一致的界面结构可以降低用户学习成本。

**独立测试**: 可以通过以下操作独立测试:用户在配置表单页面编辑执行函数体和测试数据,点击"试运行"按钮,系统执行代码并显示运行结果(包括成功/失败状态、得分和原因)。

**验收场景**:

1. **Given** 用户选择模板后进入配置界面, **When** 页面加载完成, **Then** 页面结构包含"基础信息"和"配置信息"两个主要区域,整体布局与LLM评估器配置界面保持一致
2. **Given** 用户在配置表单页面查看基础信息区域, **When** 查看表单字段, **Then** 基础信息区域的字段(名称、描述等)与LLM评估器配置表单完全一致
3. **Given** 用户在配置表单页面, **When** 页面加载完成, **Then** 配置信息区域显示通知条"支持 Python / Javascript 内置库,部分三方库。更多使用说明参见 Code 评估器手册"(其中"Code 评估器手册"为超链接),通知条可手动关闭
4. **Given** 用户在配置表单页面, **When** 用户查看配置信息区域, **Then** 区域采用左右两栏布局,左侧栏显示"执行函数体"配置(包含标题、语言选择下拉框和代码编辑器),右侧栏显示"测试数据"配置(包含标题、info图标和JSON编辑器)
5. **Given** 用户选择了模板创建, **When** 用户尝试切换语言, **Then** 语言下拉框不可修改
6. **Given** 用户选择了自定义创建, **When** 用户切换语言, **Then** 执行函数体代码编辑区域被清空并替换为对应语言的初始化代码
7. **Given** 用户在配置表单页面, **When** 用户查看代码编辑器和JSON编辑器, **Then** 两个编辑器都支持语法高亮、自动补全和语法检查
8. **Given** 用户编辑了执行函数体和测试数据, **When** 用户点击"试运行"按钮, **Then** 系统使用测试数据执行函数体,在配置区域下方显示试运行结果包括:总条数、成功条数、失败条数、状态(loading/success/fail)、得分、原因
9. **Given** 用户在编辑过程中, **When** 用户点击"选择模板"按钮, **Then** 系统展开选择模板弹窗,用户选择模板点击确定后,当前配置内容被选中模板内容覆盖(但评估器名称保持不变)
10. **Given** 用户在配置表单页面, **When** 用户点击全屏按钮, **Then** 系统展开全屏弹窗,包含执行函数体、测试数据编辑区域和试运行结果区域,用户可在弹窗内直接试运行

**功能需求**:

- **FR-200**: Code评估器配置界面的整体结构必须与LLM评估器配置界面保持一致,包含"基础信息"和"配置信息"两个主要区域
- **FR-201**: 基础信息区域的所有表单字段(名称、描述等)必须与LLM评估器配置表单完全一致
- **FR-202**: 配置信息区域必须在标题下方显示通知条,内容为"支持 Python / Javascript 内置库,部分三方库。更多使用说明参见 Code 评估器手册",其中"Code 评估器手册"为超链接指向https://loop.coze.cn/open/docs/cozeloop/create_evaluators
- **FR-203**: 通知条必须可以手动关闭,关闭仅针对本次新建流程生效
- **FR-204**: 配置信息区域必须采用左右两栏布局。左侧栏必须显示执行函数体配置区域,包含标题"执行函数体"和语言选择下拉框(Python/Javascript),下方显示代码编辑器
- **FR-205**: 执行函数体代码编辑器必须支持语法高亮、自动补全(AutoComplete)和语法检查
- **FR-206**: 如果用户通过模板创建评估器,语言选择下拉框必须不可修改(锁定为模板语言)
- **FR-207**: 如果用户通过自定义创建评估器,语言选择下拉框必须可修改,切换语言后代码编辑区域必须清空并替换为对应语言的初始化代码
- **FR-208**: Python初始化代码必须包含完整的示例函数结构和详细注释
- **FR-209**: Javascript初始化代码必须包含完整的示例函数结构和详细注释
- **FR-210**: 配置信息区域的右侧栏必须显示测试数据配置区域,包含标题"测试数据:turn"和info图标,下方显示JSON代码编辑器
- **FR-211**: info图标必须在鼠标悬停时显示tooltip,内容为"turn 代表单轮问答的评测场景,其中:\nevaluate_dataset_fields:评测集字段\nevaluate_target_output_fields:评测对象字段\next:补充字段\n 详细内容请参考文档",其中"文档"为超链接指向https://loop.coze.cn/open/docs/cozeloop/create_evaluators
- **FR-212**: 测试数据编辑器必须支持JSON格式,包含初始化数据,支持语法高亮、自动补全和语法检查
- **FR-213**: 初始化测试数据必须包含evaluate_dataset_fields、evaluate_target_output_fields和ext三个字段
- **FR-214**: 系统必须提供"试运行"按钮,点击后使用测试数据执行函数体
- **FR-215**: 试运行结果必须显示在执行函数体及测试数据配置区域下方
- **FR-216**: 试运行结果必须包含:总条数、成功条数、失败条数、执行状态(执行中显示loading,成功显示success,失败显示fail)、得分(成功1条得1分,失败不得分)、原因
- **FR-217**: 如果试运行失败,必须给出具体的失败报错信息
- **FR-218**: 系统必须提供"选择模板"按钮,按钮文案格式为"选择模板[(模板名称)]",如果当前为自定义创建则只显示"选择模板"
- **FR-219**: 点击"选择模板"按钮后必须展开选择模板弹窗,用户选择模板点击确定后,当前配置内容(除评估器名称外)必须被选中模板内容覆盖
- **FR-220**: 配置信息标题右侧必须提供全屏按钮,点击后展开全屏弹窗
- **FR-221**: 全屏弹窗必须包含执行函数体编辑区域、测试数据编辑区域和试运行结果区域
- **FR-222**: 全屏弹窗右上角必须提供全屏缩小按钮,点击后关闭弹窗
- **FR-223**: 用户必须能够在全屏弹窗内直接点击"试运行"按钮查看试运行结果

**边缘情况与处理方案**:

- **代码语法错误**: 当执行函数体代码存在语法错误时,代码编辑器内必须显示语法错误提示(如行号标记、错误下划线)。用户仍可点击"试运行"按钮,试运行执行后会在试运行结果区域显示状态为"失败",并在"原因"字段中明确展示语法错误的具体行号和错误描述(如"第5行: SyntaxError: invalid syntax")
- **测试数据JSON格式错误**: 当测试数据JSON格式不正确时,JSON编辑器内必须显示语法报错提示(如高亮错误位置、错误下划线)。用户仍可点击"试运行"按钮,试运行执行后会因为JSON格式问题而失败,并在试运行结果区域显示状态为"失败",原因字段中显示具体的JSON解析错误信息(如"JSON格式错误: Unexpected token } at position 45")
- **切换模板**: 当用户编辑了配置内容后点击"选择模板"按钮并选择新模板时,系统必须直接用新模板内容覆盖当前配置内容(评估器名称保持不变),无需弹出确认对话框,提升操作效率
- **代码执行超时**: 执行函数体代码必须设置30秒超时限制,如果执行超过30秒,系统必须强制终止执行,并在试运行结果中显示状态为"失败",原因为"执行超时(>30秒),请检查代码是否存在死循环或性能问题"

### 用户场景 3 - 提交Code评估器并通过静态代码检查 (优先级: P1)

用户完成了Code评估器的配置和调试,现在想要提交创建评估器。系统需要在提交前自动进行静态代码检查,确保代码的基础语法、静态类型和依赖包都符合要求,只有通过检查后才能成功创建评估器。

**为什么是此优先级**: 代码检查是保证Code评估器质量和安全性的关键环节,是创建流程的最后一道关卡,必须确保用户提交的代码符合基本规范。

**独立测试**: 可以通过以下操作独立测试:用户在配置表单页面点击"创建"按钮,系统弹出"提交前代码检查"弹窗,自动运行静态检查,如果检查失败则提交按钮不可点击,用户修改代码后重新检查直到通过,点击提交成功创建评估器。

**验收场景**:

1. **Given** 用户在配置表单页面填写完所有必填项, **When** 用户点击"创建"按钮, **Then** 系统弹出"提交前代码检查"弹窗,弹窗内显示执行函数体编辑区域(可编辑),下方自动开始运行静态代码检查
2. **Given** 系统正在运行静态代码检查, **When** 检查进行中, **Then** 系统依次显示"基础语法检查中"、"静态类型检查中"、"依赖包检查中"的进度提示
3. **Given** 静态代码检查完成, **When** 所有检查项都通过, **Then** 执行函数体编辑区域下方显示检查结果:状态为"通过",提交按钮变为可点击状态
4. **Given** 静态代码检查完成, **When** 存在检查项不通过, **Then** 执行函数体编辑区域下方显示检查结果:状态为"不通过",具体的检查结果信息,提交按钮保持不可点击状态
5. **Given** 代码检查不通过, **When** 用户在弹窗内修改了代码, **Then** 用户可以点击"重新检查"按钮再次运行静态检查
6. **Given** 代码检查通过, **When** 用户点击"提交"按钮, **Then** 系统成功创建版本为0.0.1的Code评估器,并自动跳转到评估器详情页

**功能需求**:

- **FR-301**: 用户点击配置表单的"创建"按钮后,系统必须弹出"提交前代码检查"弹窗
- **FR-302**: 弹窗内必须显示执行函数体编辑区域,用户可以审阅和编辑代码
- **FR-303**: 弹窗打开后必须自动开始运行静态代码检查,无需用户手动触发
- **FR-304**: 静态代码检查必须依次进行:基础语法检查、静态类型检查、依赖包检查
- **FR-305**: 检查过程中必须显示当前检查阶段的进度提示
- **FR-306**: 检查完成后必须在执行函数体编辑区域下方显示检查结果,包括结果状态(通过/不通过)和检查结果信息
- **FR-307**: 如果检查不通过,提交按钮必须保持不可点击状态
- **FR-308**: 如果检查不通过,必须提供"重新检查"按钮,用户修改代码后可点击重新运行检查
- **FR-309**: 如果检查通过,提交按钮必须变为可点击状态
- **FR-310**: 用户点击提交按钮后,系统必须创建版本为0.0.1的Code评估器
- **FR-311**: 创建成功后,系统必须自动跳转到评估器详情页

**边缘情况与处理方案**:

- **检查过程中关闭弹窗**: 当用户在静态代码检查进行中关闭弹窗时,系统必须立即取消正在进行的检查任务,并清理相关资源。用户下次点击"创建"按钮时重新开始完整的检查流程
- **并发检查请求**: 当用户多次快速点击"重新检查"按钮时,系统必须禁用"重新检查"按钮并显示loading状态,直到当前检查完成。同一时刻只允许一个检查任务运行,新的检查请求必须等待当前检查完成或取消
- **静态检查服务不可用**: 当静态检查服务不可用或超时(30秒)时,系统必须在检查结果区域显示状态为"检查失败",错误信息为"代码检查服务暂时不可用,请稍后重试",提交按钮保持不可点击状态,允许用户重新检查或关闭弹窗

### 用户场景 4 - 查看和试运行Code评估器详情 (优先级: P2)

用户成功创建了Code评估器后,需要查看评估器的详情信息,包括基础信息和配置信息。用户也可能想要在详情页再次试运行评估器,验证其功能是否符合预期。

**为什么是此优先级**: 详情页是用户查看和管理已创建评估器的入口,虽然不是创建流程的一部分,但对于后续的评估器管理和使用同样重要。

**独立测试**: 可以通过以下操作独立测试:用户创建评估器后自动跳转到详情页,或从评估器列表点击某个Code评估器进入详情页,查看配置信息区域显示执行函数体和测试数据,点击"试运行"按钮可以执行评估器并查看结果。

**验收场景**:

1. **Given** 用户成功创建了Code评估器, **When** 系统跳转到评估器详情页, **Then** 页面显示评估器的基础信息(名称、版本、创建时间等)和配置信息(执行函数体、测试数据)
2. **Given** 用户在评估器详情页, **When** 用户查看配置信息区域, **Then** 显示的内容与配置表单页面的配置信息区域一致(包括执行函数体、测试数据、试运行结果)
3. **Given** 用户在评估器详情页, **When** 用户点击"试运行"按钮, **Then** 系统执行评估器,试运行结果显示在配置区域中的试运行结果区域
4. **Given** 用户在评估器详情页, **When** 用户对比LLM评估器详情页, **Then** Code评估器详情页的交互逻辑与LLM评估器详情页保持一致,差异仅在于配置信息区域显示的是Code评估器特有的内容,以及"调试"按钮被替换为"试运行"按钮

**功能需求**:

- **FR-401**: Code评估器详情页必须显示评估器的基础信息(名称、版本、创建时间、描述等)
- **FR-402**: Code评估器详情页的配置信息区域必须显示执行函数体和测试数据
- **FR-403**: 配置信息区域的显示内容和交互必须与配置表单页面保持一致
- **FR-404**: 详情页必须提供"试运行"按钮(替代LLM评估器的"调试"按钮)
- **FR-405**: 点击"试运行"按钮后,系统必须执行评估器
- **FR-406**: 试运行结果必须显示在配置区域中的试运行结果区域
- **FR-407**: 除配置信息区域和按钮差异外,Code评估器详情页的整体交互逻辑必须与LLM评估器详情页保持一致

**边缘情况与处理方案**:

- **版本更新后的详情显示**: 当评估器有多个版本时,详情页必须默认显示最新版本的配置信息。页面必须提供版本选择下拉菜单,允许用户切换查看其他版本,切换版本后配置信息区域内容相应更新
- **详情页修改配置**: 详情页的配置信息必须为只读模式,不允许直接修改。如果用户需要修改配置,必须点击"编辑"按钮(如果提供),系统创建新版本并进入编辑模式,或者用户需要基于当前版本创建新的评估器

### 用户场景 5 - 在评估器列表中识别评估器类型 (优先级: P2)

用户在评估器列表页面浏览时,需要快速识别哪些是LLM评估器,哪些是Code评估器。系统需要在列表中清晰地展示评估器的类型信息。

**为什么是此优先级**: 类型识别是用户管理多个评估器的基础功能,有助于用户快速找到目标评估器,但不影响核心创建流程。

**独立测试**: 可以通过以下操作独立测试:用户进入评估器列表页面,查看列表第二列显示"类型"列,每个评估器对应显示"Code"或"LLM"类型标识,用户可以在列管理中配置"类型"列的显隐。

**验收场景**:

1. **Given** 用户在评估器列表页面, **When** 页面加载完成, **Then** 列表第二列显示"类型"列,展示每个评估器的类型("Code"或"LLM")
2. **Given** 用户在评估器列表页面, **When** 用户打开列管理配置, **Then** 列管理中包含"类型"列的显隐配置选项,默认勾选(显示)
3. **Given** 用户在列管理中取消勾选"类型"列, **When** 用户关闭列管理, **Then** 列表中"类型"列被隐藏
4. **Given** 用户在列管理中重新勾选"类型"列, **When** 用户关闭列管理, **Then** 列表中"类型"列重新显示

**功能需求**:

- **FR-501**: 评估器列表必须在第二列新增"类型"列
- **FR-502**: "类型"列必须显示每个评估器的类型,可选值为"Code"和"LLM"
- **FR-503**: 列管理功能必须支持对"类型"列的显隐配置
- **FR-504**: "类型"列在列管理中必须默认勾选(显示状态)

**边缘情况与处理方案**:

### 用户场景 6 - 在实验中选择和使用Code评估器 (优先级: P2)

**为什么是此优先级**: 这是Code评估器的实际使用场景,虽然依赖于评估器的创建,但是整个功能闭环的重要组成部分。

**独立测试**: 可以通过以下操作独立测试:用户在创建实验的第四步选择评估器时,能够看到并选择Code类型的评估器,选择后下方显示只读的执行函数体代码,在最后的提交确认阶段也能看到Code评估器的执行函数体代码。

**验收场景**:

1. **Given** 用户在创建实验的第四步(选择评估器), **When** 用户查看可选评估器列表, **Then** 列表中包含当前空间内已创建完成的Code类型评估器

4. **Given** 用户在实验的各个阶段查看评估器信息, **When** 显示评估器名称的区域, **Then** 评估器名称左侧必须显示评估器类型名称("Code"或"LLM")

**功能需求**:

- **FR-601**: 新建实验第四步的评估器选择列表必须包含当前空间内已创建完成的Code类型评估器
- **FR-602**: 选择Code评估器并选择版本后,下方详情区域必须显示该版本的执行函数体代码
- **FR-603**: 执行函数体代码必须以只读模式显示
- **FR-604**: 在提交前确认阶段,如果选择了Code评估器,对应详情必须展示只读的执行函数体代码
- **FR-605**: 在实验阶段所有展示评估器名称的区域,必须在评估器名称左侧显示评估器类型名称("Code"或"LLM")

- **评估器被删除或禁用**: 当用户在实验配置中选择的Code评估器被删除或禁用时,系统必须在实验详情页显示警告提示"该评估器(名称)已被删除/禁用,实验结果可能不准确"。如果评估器被删除,用户必须重新选择其他评估器才能继续运行实验;如果仅是禁用,已配置的实验仍可继续使用该评估器的现有版本

## 核心实体 _(包含数据的功能需包含此部分)_

- **评估器(Evaluator)**: 代表一个评估器实例,包含类型(LLM/Code)、名称、描述、版本号、创建时间、创建者等基础属性。对于Code类型评估器,还包含执行函数体代码、编程语言类型(Python/Javascript)等特有属性。

- **评估器模板(Evaluator Template)**: 代表预置的评估器模板,包含模板名称、模板类型(Code/LLM)、支持的编程语言(仅Code类型)、执行函数体代码(仅Code类型)或配置内容(LLM类型)等属性。用于在创建流程中为用户提供快速启动的基础。**所有类型的评估器创建都需要经过模板选择流程**。

- **评估器版本(Evaluator Version)**: 代表评估器的某个具体版本,包含版本号、配置内容(执行函数体、测试数据等)、创建时间等属性。每次评估器配置的修改都会生成新的版本。

- **实验(Experiment)**: 代表一个评测实验,包含实验名称、关联的评估器列表(可包含LLM和Code类型)、评测集、评测对象等属性。

- **静态检查结果(Static Check Result)**: 代表Code评估器提交前的静态检查结果,包含检查状态(通过/不通过)、基础语法检查结果、静态类型检查结果、依赖包检查结果、错误信息等属性。
